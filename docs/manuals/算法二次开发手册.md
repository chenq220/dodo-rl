# 算法二次开发说明

`algos` 目录负责把外部算法或自研算法接入框架。一个可训练算法通常由四部分组成：

1. `config.py` 中的算法配置
2. `src/algos/training/` 下的 Learner 实现
3. `src/algos/modules/` 下的 Agent、Critic 和 Mixer 组件
4. `src/algos/builtin_plugins.py` 中的内置插件注册，以及 `src/algos/map.py` 中供 Python 调用的类型映射

## 目录职责

- 从 `algos.agents` 导入 `Agent`、`AgentInputShape` 和动作记录装饰器，从 `algos.learners` 导入 `Learner`。
- `src/algos/modules/agents/` 放执行策略与网络。COMA 和 MAPPO 共用 `PolicyRNNAgent`，SB3 的 PPO、A2C、DQN 共用 `SB3Agent`。
- `src/algos/modules/critics/` 放 COMA、MAPPO、MADDPG 的集中式 Critic，`src/algos/modules/mixers/` 放 QMIX Mixer。
- `src/algos/training/` 组合组件并实现训练更新。跨算法的批次视图、循环输入和运行统计放在 `src/algos/utils/`。
- `src/algos/learners/batch_schema.py` 声明训练张量字段和组装规则，和 `Learner` 基类一起维护。`EpisodeBatch` 数据容器由 `src/sample/model.py` 提供。

## 第一步：定义算法配置

内置算法的配置定义在 `src/config.py`。增加算法名及其配置类，再将二者关联。

1. 在 `AlgorithmType` 中增加算法名。
2. 定义继承 `LearnerAlgoConfig` 的算法配置类。
3. 在 `LEARNER_ALGO_CONFIG` 中注册算法类型和配置类。

示例：

```python
class AlgorithmType(ConfigEnum):
    DQN = "dqn"


@dataclass
class DqnConfig(LearnerAlgoConfig):
    default_agent_type: ClassVar[str] = AgentType.SB3.value
    lr: float = 1e-4
    batch_size: int = 16
    learn_times_per_episode: int = 1
    agent_output_type: AgentOutputType = AgentOutputType.Q
    sample_strategy: str = SamplingStrategy.RECENT_BIASED.value
    train_batch_size: int = 64


LEARNER_ALGO_CONFIG = {
    AlgorithmType.DQN: DqnConfig,
}
```

`default_agent_type` 由配置类声明。训练 TOML 中，Agent 与 Learner 通过 `name` 配对，省略 `agent_type` 时由同名 Learner 选择默认 Agent。显式填写可覆盖默认选择。

配置类分两层：

- `LearnerConfig`：Learner 骨架配置，放算法通用字段和运行期维度。
- `DqnConfig` / `QmixConfig` / `PpoConfig`：算法私有配置，放算法真正关心的超参。

算法配置必须声明这些通用字段：

- `lr`
- `batch_size`
- `learn_times_per_episode`
- `agent_output_type`

其中 `agent_output_type` 决定执行侧 Agent 如何解释网络输出：

- `q`：网络输出动作 Q 值，执行侧通常使用 epsilon-greedy。
- `pi_logits`：网络输出策略 logits 或策略分布，执行侧按概率采样或 argmax。

## 第二步：实现 Learner

Learner 放在 `src/algos/training/`。例如 DQN 在 `src/algos/training/sb3_dqn_learner.py` 继承公共基类，并通过 `@learner_plugin(DqnConfig)` 绑定配置类型。

```python
from algos.learners import Learner
from common.plugins import learner_plugin
from config import DqnConfig
```

Learner 需要继承 `Learner` 基类，并实现以下关键接口：

- `agent_net`：返回可被 Agent 克隆的执行网络。
- `models`：返回需要提交给 ModelManager 的网络字典。
- `build_empty_network()`：构建空网络。
- `build_network_from_checkpoint()`：从模型文件或模型池权重恢复网络。
- `update(batch_data)`：执行一次训练更新，返回该次更新各项指标数据如loss、td_error_abs等。
- `snapshot_state()`：返回当前需要保存的全部训练状态，用于任务重启/阶段切换时恢复。
- `restore_state(state)`：从 `snapshot_state` 返回值恢复训练状态。
- `dynamic_modify_config(updates)`：按任务令牌动态同步算法超参；入参为 `dict`，仅覆盖传入字段。
- `save_models()`：保存模型文件。默认实现遍历 `models` 按统一命名规范落盘，一般无需覆盖。

`snapshot_state` / `restore_state` 是任务重启闭环的唯一算法侧入口。框架在任务重启或阶段切换时会自动调用这两个方法存盘/恢复，开发者只需要告诉框架“我的算法有哪些状态需要保存、怎么恢复回来”，不需要关心何时被调用。快照必须覆盖所有会影响下一次 `update` 结果的状态，否则重启后曲线会分叉：

- 全部网络权重的 `state_dict`（含 target / old / mixer 等辅助网络）；
- 全部优化器的 `state_dict`（动量、学习率调度状态）；
- 训练计数器、动作/回报归一化器、算法内部回放池等非网络训练状态。

`snapshot_state` 返回值会被框架整体深拷贝后存盘，因此可以直接返回对活模型 `state_dict`、计数器等的引用，无需自己再做深拷贝。建议返回 `dict`，key 用算法自有命名空间前缀以防冲突。`restore_state` 收到的是存盘的深拷贝，可以就地读取/修改。

Learner 的职责是训练，不负责业务动作选择。训练完成后，框架会通过：

```python
agent.reset_net(learner.agent_net)
```

把 Learner 的可执行网络同步给 Agent。

接入外部算法库时，Learner 通常还要做样本转换。例如 SB3 DQN 的流程是：

```text
ReplayBuffer.sample()
  -> List[SAEpisodeTransition]
  -> Learner.learn_update() 按 Learner.batch_schema 组装 EpisodeBatch
  -> 写入 stable_baselines3.DQN.replay_buffer
  -> 调用 DQN.train()
```

### Learner 接口表

| 接口名 | 需要实现 | 功能说明 | 入参说明 | 出参说明 |
| --- | --- | --- | --- | --- |
| `agent_net` | 必须 | 给出训练好的、可用于决策的策略网络。即使算法内部还有 critic、mixer 等辅助网络，对外只暴露这一个执行网络。 | 无 | 一个可执行的策略网络 |
| `models` | 必须 | 列出本算法持有的所有关键网络，便于保存和加载。 | 无 | 网络字典，形如 `{"agent_net": 网络, "critic_net": 网络}` |
| `build_empty_network(learner_config, **kwargs)` | 必须 | 从零搭建训练所需的网络结构（全新训练时用）。 | `learner_config`：算法超参与网络结构配置 | 搭建好的训练网络 |
| `build_network_from_checkpoint(checkpoint, learner_config, **kwargs)` | 必须 | 用已有权重恢复网络，用于断点续训或加载已有模型。 | `checkpoint`：已有网络权重；`learner_config`：算法配置 | 恢复好的训练网络 |
| `update(batch_data)` | 必须 | 用一批样本做一次训练更新，这是算法学习的核心。 | `batch_data`：一批训练样本 | 训练指标字典（如 loss）。样本不足可返回跳过标记 |
| `snapshot_state()` | 必须 | 返回当前需要保存的全部训练状态，用于任务重启/阶段切换时恢复。框架会整体深拷贝后存盘，子类可直接返回活模型引用。快照必须覆盖所有会影响下次 `update` 结果的状态：全部网络（含 target/old/mixer）`state_dict`、全部优化器 `state_dict`、训练计数器、归一化器、算法内部回放池等。 | 无 | 任意可深拷贝对象，建议 `dict` |
| `restore_state(state)` | 必须 | 从 `snapshot_state` 返回值恢复训练状态。传入的是存盘的深拷贝，可就地读取/修改。恢复动作应与 `snapshot_state` 一一对应。 | `state`：`snapshot_state` 返回值 | 无 |
| `save_models(save_model_path, save_model_name)` | 可选 | 把当前模型保存成文件。默认实现遍历 `models`，按 `{save_model_name}_{learner_name}_{model_key}_{generation}.pth` 命名并保存各网络 `state_dict`；仅需保存 `models` 未列出的网络或采用非 `state_dict` 格式时覆盖。 | `save_model_path`：保存目录；`save_model_name`：文件名前缀 | 已保存的文件路径列表 |
| `dynamic_modify_config(updates)` | 可选 | 训练过程中切换超参（如学习率、熵系数），常见于分阶段训练。默认实现把传入 dict 增量写入当前 `algo_config`（只覆盖传入字段，其余不变）；子类应先 `super()` 再同步框架内部状态。 | `updates: dict[str, Any]` | 无 |

## 自定义Learner 更新网络的 Batch 内容

QMIX、COMA、MAPPO 使用默认多智能体 schema；MADDPG 使用只保留训练所需字段的 `MADDPG_EPISODE_SCHEMA`，SB3 适配器使用按有效步拍平的单智能体 schema。训练代码调用 `learn_update(episodes, generation)`，框架按目标 Learner 的 schema 组装 `EpisodeBatch` 后再调用 `update(batch)`。

组批输入遵循明确的轨迹契约：多智能体使用 `EpisodeTransition`，单智能体使用 `SAEpisodeTransition`。观测、动作、奖励等必需字段由轨迹类型声明；可选字段也必须存在，用 `None` 或空容器表示未提供。多智能体完整轨迹默认 `starts_with_episode=True`、`burn_in=None`，中途切片由回放池设置边界并按需附带同组同局的历史。活动掩码允许空字典；提供时必须覆盖全部成员且每个成员的长度等于 `seq_len`，组批时校验，不将残缺掩码默认为活动。

基线组批函数直接读取这些属性，缺失属性属于输入契约错误。历史对象缺少可选字段时，由 pickle、回放快照或旧 JSON 的反序列化入口补齐。扩展算法需要额外样本时，通过 schema 和 `metadata["batch_fields"]` 声明和提供；扩展轨迹插件应继承基线并调用父类初始化。

### 当前默认 Batch Schema

`Learner.batch_schema` 的默认值是 `DEFAULT_EPISODE_SCHEMA`。QMIX、COMA、MAPPO 直接继承它，更新方法接收 `EpisodeBatch[DefaultEpisodeFields]`。MADDPG 覆盖为 `MADDPG_EPISODE_SCHEMA`，更新方法接收 `EpisodeBatch[MaddpgEpisodeFields]`，省去集中状态、burn-in 和行为策略统计等字段。按局抽样和按步抽取的轨迹片段都保留时间轴，批次中的每行对应一条轨迹或一个片段。

| 字段 | 形状 | dtype 或容器 | 内容 |
| --- | --- | --- | --- |
| `obs` | `[B, T+1, N, O]` | `float32` | 各 Agent 的观测，包含末步的下一帧 |
| `state` | `[B, T+1, S]` | `float32` | 全局状态，包含末步的下一帧 |
| `actions`、`last_actions` | `[B, T, N, D]` | 离散 `int64`，连续 `float32` | 当前动作和上一动作的编码，由已绑定的 `ActionSpace` 确定 |
| `rewards` | `[B, T, N]` | `float32` | 各 Agent 的奖励 |
| `team_rewards` | `[B, T]` | `float32` | 每步团队奖励 |
| `terminated`、`truncated` | `[B, T, N]` | `bool` | 各 Agent 的真实终止与截断标志 |
| `team_terminated` | `[B, T]` | `bool` | 团队真实终止标志 |
| `valid` | `[B, T]` | `bool` | 本批有效步，区分轨迹数据与补齐位置 |
| `active` | `[B, T+1, N]` | `bool` | 各帧的活动 Agent 槽位，包含末帧 |
| `starts_with_episode` | `[B]` | `bool` | 轨迹或片段是否从局首开始 |
| `action_masks` | `[B, T+1, N, A]` | `bool \| None` | 离散动作可用掩码，包含末帧 |
| `old_log_probs`、`temperature` | `[B, T, N]` | `float32 \| None` | 采样时的行为对数概率与温度，依赖采样记录 |
| `hidden_in` | `[B, N, L, H]` | `float32 \| None` | 采样记录的初始循环隐藏状态 |
| `burn_in` | 长度 `B` | `list[EpisodeTensorFields \| None]` | 每行对应的循环历史前缀，供非局首片段重建隐藏状态 |

`B` 是本批轨迹或片段数，`T` 默认取其中最长有效步数，`T+1` 为每条轨迹预留末步下一帧。组装时按照轨迹成员顺序对齐 `N` 个固定 Agent 槽位。`O` 是单 Agent 观测宽度，`S` 是全局状态宽度，`D` 是动作编码宽度，`A` 是离散动作掩码宽度，`L`、`H` 分别是循环层数和隐藏维度。例如抽到 2 条长度分别为 3 和 2 的轨迹，`obs` 为 `[2, 4, N, O]`，`rewards` 为 `[2, 3, N]`。第二条轨迹的 `valid` 是 `[True, True, False]`。

SB3 的 PPO、A2C、DQN 显式声明 `batch_schema = SINGLE_AGENT_SCHEMA`，更新方法接收 `EpisodeBatch[SingleAgentFields]`。该契约按有效步拍平，`M` 是抽到的有效步总数，上例的 `M` 为 5。

| 字段 | 形状 | dtype 或容器 | 内容 |
| --- | --- | --- | --- |
| `obs`、`next_obs` | `[M, O]` | `float32` | 每步的当前与下一观测 |
| `actions`、`last_actions` | `[M, D]` | `int64` | 离散动作编码 |
| `rewards` | `[M, 1]` | `float32` | 每步奖励 |
| `terminated`、`truncated`、`episode_starts` | `[M, 1]` | `float32` | 以 0 或 1 表示终止、截断及局首 |
| `avail_actions` | `[M, A]` | `float32 \| None` | 动作可用掩码 |
| `old_log_probs`、`old_values`、`returns`、`advantages` | `[M, 1]` | `float32 \| None` | 可用的策略统计和训练量 |
| `metadata` | 字典 | `dict` | 批次哈希 `batch_hash` 与逐步去重键 `transition_keys` |

### 自定义 Batch Schema

1. 用 `TypedDict` 声明 `update()` 要读取的字段。字段名是 `batch.data` 的键，`source` 指向数据来源。源码中的描述符从 `algos.learners.batch_schema` 导入，SDK 通过 `dodorl_sdk.algorithms` 提供同一套接口。
2. 用 `Annotated` 给字段绑定描述符。张量用 `TensorField(source, axes, dtype, padding_value=None)`，`axes` 按输出维度顺序排列，可将内置来源从批次优先换成时间优先。用 `dtype=None` 保留来源 dtype，默认动作字段由 `ActionSpace` 产生整型或浮点编码。`padding_value` 指定无效时间位置的填充值。逐局列表用 `ListField(source, "B")`，已有字典来源用 `DictField(source)`，也可以用嵌套 `TypedDict` 逐项声明子字段。需要允许整个字段缺省时将类型写成 `Tensor | None`。
3. 在 Learner 子类上设置 `batch_schema = BatchSchema.from_type(MyFields)`，并为 `update()` 注解 `EpisodeBatch[MyFields]`。框架在调用 `update()` 前根据 schema 组装张量并检查字段和形状。

以下示例用时间优先的观测张量、掩码字典和逐轨迹长度列表定义批次，并增加每步、每个 Agent 的标量 `policy_score`。

```python
from typing import Annotated, TypedDict
import torch
from dodorl_sdk.algorithms import BatchSchema, EpisodeBatch, Learner, ListField, TensorField

class Masks(TypedDict):
    valid: Annotated[torch.Tensor, TensorField("valid", ("T", "B"), torch.bool)]
    active: Annotated[torch.Tensor, TensorField("active_steps", ("T", "B", "N"), torch.bool)]

class MyFields(TypedDict):
    obs: Annotated[torch.Tensor, TensorField("obs_with_bootstrap", ("T+1", "B", "N", "O"), torch.float32)]
    score: Annotated[torch.Tensor, TensorField("policy_score", ("T", "B", "N"), torch.float32)]
    masks: Masks
    lengths: Annotated[list[int], ListField("seq_len", "B")]

class MyLearner(Learner[MyFields]):
    batch_schema = BatchSchema.from_type(MyFields)

    def update(self, batch: EpisodeBatch[MyFields]):
        fields = batch.data
        active = fields["masks"]["active"] & fields["masks"]["valid"].unsqueeze(-1)
        scores = fields["score"][active]
        return {"mean_score": scores.mean().item() if scores.numel() else 0.0}

    # 还需按 Learner 接口实现模型构造、保存及快照方法。
```

`obs_with_bootstrap`、`valid`、`active_steps` 和 `seq_len` 来自轨迹。`policy_score` 由配对 Agent 在 `get_actions()` 时计算，采样器随后调用它的 `consume_rollout_fields(names)`。收到 `policy_score` 请求时返回 `{"policy_score": {agent_id: value}}`，覆盖本步所有活动 Agent。采样器把值写进该步的 `metadata["batch_fields"]`，回放抽取后再按 `(T, B, N)` 组装。单智能体拍平布局可用 `TensorField("policy_score", ("M",), torch.float32)`。

需要保留自定义字段的原始逐步值时，可以声明 `Annotated[list[list[dict[str, float]]], ListField("policy_score", "B")]`，得到按轨迹、局内步和 AgentID 对齐的值。

## 第三步：实现或复用 Agent

Agent 实现在 `src/algos/modules/agents/`，从 `algos.agents` 导入基类。新增 Agent 使用 `@agent_plugin(MyAgentConfig)` 声明自己的配置类型。Agent 通过统一的 `get_actions(obs, agent_list, hidden_in)` 返回按成员索引的业务动作和下一步隐藏状态。

如果新算法的可执行网络和已有 Agent 兼容，可以复用已有 Agent。例如：

- `PPO/A2C` 复用 `SB3Agent` 的 `ActorCriticPolicy` 分支。
- `DQN` 复用 `SB3Agent` 的 `DQNPolicy` 分支。
- `QMIX` 支持 `rnn`、`rnn_ns` 和 `q_rnn`，动作空间为单头离散。
- `MAPPO` 和 `COMA` 使用 `policy_rnn`；COMA 支持单头离散、单头连续和多头连续动作。

只有当算法需要新的执行网络结构或新的动作选择逻辑时，才新增 Agent。

Agent 至少要实现：

- `get_actions()`

动作输出由 `ActionSpace` 解码为业务动作对象，覆盖离散、连续和多头布局。设置 `config.algo_config.use_net = false` 可构造跳过网络初始化的执行策略。

### Agent 接口表

| 接口名 | 需要实现 | 功能说明 | 入参说明 | 出参说明 |
| --- |------| --- | --- | --- |
| `get_actions(...)` | 必须   | 根据当前观测决定每个智能体要做的动作，这是执行期的核心。 | 当前观测、待决策的智能体清单、隐藏状态、动作掩码、探索系数、是否评估等 | 动作实体 `Action` 和更新后的隐藏状态 |
| `build_empty_network(dim_info, **kwargs)` | 可选   | 从零搭建决策所需的网络结构（全新启动时用）。规则类策略也需返回一个占位网络。 | `dim_info`：输入/输出维度信息 | 搭建好的执行网络 |
| `build_network_from_checkpoint(checkpoint, dim_info, **kwargs)` | 可选   | 用已有权重恢复决策网络，用于加载训练好的模型上场。 | `checkpoint`：已有网络权重；`dim_info`：维度信息 | 恢复好的网络及其权重 |
| `get_init_hidden_state()` | 可选   | 给出每个智能体的初始隐藏状态（带记忆的策略需要）。 | 无 | 各智能体的初始隐藏状态；无记忆策略可返回空占位 |
| `reset_net(model)` | 可选   | 用新的网络刷新自己的决策网络（训练更新后同步最新模型）。默认实现把传入的网络深拷贝为自己的决策网络并切到评估模式；若需联动其他操作可重写。 | `model`：新的网络 | 无 |

## 第四步：注册算法和 Agent

在 `src/algos/builtin_plugins.py` 的 `BUILTIN_LEARNER_PLUGINS` 字典里登记 Learner 的插件名和实现路径。源码 Portal 和 SDK 共用这份清单。以 DQN 为例，条目写为下列形式。

```python
"dqn": "algos.training.sb3_dqn_learner:SB3DQNLearner",
```

新增 Agent 时，在同文件的 `BUILTIN_AGENT_PLUGINS` 登记 `"my_agent": "algos.modules.agents.my_agent:MyAgent"`。复用已有 Agent 时，Learner 的 `default_agent_type` 可以直接引用现有插件标识。

在 `src/algos/map.py` 中为需要从 Python 配置的内置算法提供 `AlogsMap` 类型入口。

```python
class _Dqn:
    learner = _TypedRef(AlgorithmType.DQN.value, DqnConfig)
    agent = _SB3Agents
    algo_type = AlgosType.QLearning


class AlogsMap:
    dqn = _Dqn
```

入口处就可以写：

```python
algo_ref = AlogsMap.dqn
agent_config = AgentConfig(agent_type=algo_ref.agent.sb3)
learner_config = LearnerConfig(algo_type=algo_ref.learner)
```

## 开发检查清单

新增算法时至少检查这些点：

- `AlgorithmType` 已注册。
- `LearnerAlgoConfig` 子类已加入 `LEARNER_ALGO_CONFIG`。
- Learner 已加入 `BUILTIN_LEARNER_PLUGINS`，新增的 Agent 已加入 `BUILTIN_AGENT_PLUGINS`。
- `AlogsMap` 已加入算法节点。
- Agent 类型和 Learner 支持关系在 Learner `__init__` 中有断言。
- `agent_output_type` 和 Agent 执行动作逻辑一致。
- `Learner.agent_net` 返回的是 Agent 能 `reset_net()` 的网络类型。
- `models` 列出了需要落盘保存的全部关键网络；默认 `save_models` 会按 `{prefix}_{learner}_{model_key}_{generation}.pth` 逐个保存。
- `update()` 使用任务令牌下发的算法超参，不偷偷读取不该读取的默认值。
- `snapshot_state` 覆盖了全部网络（含 target/old/mixer）、全部优化器、训练计数器与归一化器等会影响下次 `update` 结果的状态；`restore_state` 与之一一对应。
- 样本格式转换边界清晰，不把算法私有样本格式污染到 `ReplayBuffer`。
- 至少跑一次 `compileall` 和一个最小训练 smoke test；契约项校验失败应统一抛出 `AlgoConformanceException`。
- 算法接入完成后跑一遍规范性发烟测试（见下一节）。

## 规范性发烟测试

`sdk/algo_conformance/` 目录归档二次开发算法的规范性发烟用例，对照本手册接口表自动检查：

- 接口齐全性：必须实现的接口是否仍是抽象方法（`InterfaceMissingException`）；
- 契约符合性：返回值类型/形状/语义是否满足契约（`ContractViolationException`）；
- 功能可用性：`build` / `update` / `snapshot` / `restore` / `save` / `get_actions` / `reset_net` 端到端能否跑通（`FunctionalityException`）。

三个异常均继承 `AlgoConformanceException`，发烟测试统一捕获它即可判定算法接入未通过规范性检查。

### 目录结构

- `conformance.py`：发烟测试脚手架（合并了描述符数据结构、检查工具、TOML 加载、通用环境桩和 episode 工厂）。
- `qmix.toml`：QMIX 算法 conformance 配置文件。
- `run_test.py`：CLI runner，支持 `-f` 指定配置文件、`--only` 选择 learner/agent。
- `test_learner_conformance.py`：Learner 规范性发烟测试（pytest 入口 + 可被 runner 调用）。
- `test_agent_conformance.py`：Agent 规范性发烟测试（同上）。

### TOML 配置格式

为已实现并注册的算法准备一份 TOML，用 `[conformance]` 指向需要检查的类。

```toml
[conformance]
algo_dir = ""                 # 算法代码目录，加入 sys.path；框架内置算法留空
learner_import_path = "algos.training.qmix_learner.QMixerLearner"
agent_import_path = "algos.modules.agents.rnn_agent.RNNAgent"
sample_type = "multi_agent"   # multi_agent -> EpisodeTransition，single_agent -> SAEpisodeTransition
episode_steps = 4             # 每局步数
episode_count = 2             # 触发一次 update 所需 episode 数
```

### 运行

CLI runner（推荐，从 TOML 加载配置）：

```bash
# 框架内置算法
python sdk/algo_conformance/run_test.py -f sdk/algo_conformance/qmix.toml

# 自定义算法（algo_dir 在 TOML 的 [conformance] 小节中声明）
python sdk/algo_conformance/run_test.py -f /path/to/my_algo.toml

# 只跑 learner 或 agent
python sdk/algo_conformance/run_test.py -f sdk/algo_conformance/qmix.toml --only learner
```

不要用 `python -m sdk.algo_conformance...`（会经过 `sdk/__init__.py` 拉起 SDK 运行时）。

pytest 默认只收集 `tests/`；完整 conformance 用上面的 CLI。框架内 QMIX 接入契约仍由 `tests/test_native_qmix_parity.py` 覆盖。

退出码：0=全部通过，1=有规范性检查失败。

## 常见算法形态

- Q-learning 系：通常使用 `agent_output_type = q`，执行侧 epsilon-greedy。
- Policy gradient / actor-critic 系：通常使用 `agent_output_type = pi_logits`，执行侧按策略分布采样。
- 多智能体值分解：Learner 内部可能同时包含 Agent 网络和 Mixer 网络，但对外仍通过 `agent_net` 暴露执行网络。
- 外部库算法：优先把外部库对象封装在 Learner 内部，Agent 只持有可执行网络。

## 命名建议

- Learner 文件：`sb3_dqn_learner.py`、`qmix_learner.py`
- Agent 文件：`sb3_agent.py`、`rnn_agent.py`
- 配置类：`DqnConfig`、`QmixConfig`
- 算法名：小写字符串，例如 `"dqn"`、`"qmix"`

算法内容可以复杂，但接入边界要保持简单：配置负责计划，Learner 负责训练，Agent 负责动作，注册表负责组装。

## AutoML 可消费的 update 输出与 TunableParam 契约

AutoML 配置见 **[TOML 配置手册](toml配置手册.md#18-auto_ml_config)**；各算法可调参数由 [`ALGO_TUNABLE_PARAM`](../../src/scheduler/model.py) 注册。

### 设计原则

- `update()` 仍返回普通 `dict`（RPC 友好）；**不要求** Learner 实现 `UpdateMetric` 或 `tunable_param_enum()`。
- **Optuna `trial.report` 主指标**可来自四种内置指标，也可由标准 PettingZoo `infos` / 环境 metadata 输出经安全表达式合成；不用 learn 指标做主目标。
- **可调超参**由框架 `ALGO_TUNABLE_PARAM[algo_type]` + TOML `learner_search_space` 定义；AutoML 按 `LearnerConfig.algo_type` 查表，不询问 Learner。

### update() 字典 — 归档与推荐键名

`algos_metrics.csv` **原样写入** `learn_results` 中各 learner 上报的键（列名 `{learner}_{metric_key}`），不按白名单过滤；仅跳过框架键 `skip_update`、`skip_reason`。业务输出按名称分别写入 `<name>_metrics.csv`。

[`AUTOML_LEARN_METRIC_KEYS`](../../src/scheduler/model.py) 表列出各算法**推荐**的 canonical 键名，便于二次开发与 SB3 键规范化对照，**非**归档准入条件：

| 算法 | canonical 键（节选） |
|------|---------------------|
| QMIX | `loss`, `grad_norm`, `td_error_abs`, `q_taken_mean`, `target_mean` |
| MAPPO | `critic_loss`, `pg_loss`, `agent_grad_norm`, `advantage_mean`, `pi_max`, ... |
| PPO | `pg_loss`, `value_loss`, `entropy_loss`, `approx_kl`, `clip_fraction`, `update_cnt` |
| A2C | `pg_loss`, `value_loss`, `explained_variance`, `update_cnt` |
| DQN | `loss`, `update_cnt`, `replay_size`, `inserted`, ... |

SB3 Learner 在 `_collect_stats` 内把 `train/policy_loss` 等映射为 canonical 键（可选，非强制）。

### TunableParam — 框架侧注册（非 Learner 契约）

新增算法时，在 `scheduler/model.py` 增加 `*TunableParam` 枚举并注册到 `ALGO_TUNABLE_PARAM`；TOML 使用编号表 `[stages.N.auto_ml_overrides.learner_search_space.M]`，通过 `agent_name` 与 `path` 选择参数并可选收窄范围。各算法可选 key 与默认范围见 [`ALGO_TUNABLE_PARAM` 及对应枚举](../../src/scheduler/model.py)。

数据流：`update() dict` → `learn_results` → 归档 csv；三类搜索入口 → Optuna `ask()` → restart 写回 Learner / `task_config.env_metadata` / `task_config.seed`。
